# Notes

One file per topic. Each note follows the same shape:

- Summary — the pattern in two or three sentences
- Vulnerable pattern — what the bad code looks like
- Safe pattern — how it should be written
- Review checks — what to grep / read for during a review
- My examples — sanitised examples from my own reviews (added over time)

Notes are only added when I have actually reviewed the pattern in real code
that week. No copy-pasted encyclopaedia entries.
